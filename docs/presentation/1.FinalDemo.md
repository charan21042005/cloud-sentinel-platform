## Run the AWS EKS demo

This sequence is designed to show your existing live deployment without changing the cluster. Run it from the same project directory in PowerShell.

### Step 1 — Confirm AWS and Kubernetes access

```Shell
aws sts get-caller-identity

aws eks describe-cluster `
  --name cloud-sentinel-prod `
  --region us-east-1 `
  --query "cluster.{Name:name,Status:status,Version:version}" `
  --output table

kubectl config current-context
kubectl get nodes -o wide
```



You should see the `<span>cloud-sentinel-prod</span>` cluster and two nodes in `<span>Ready</span>` state, assuming the previously observed state hasn't changed.

### Step 2 — Show the application running in Kubernetes

```Shell
kubectl get namespaces

kubectl get deployments -n sentinel-apps

kubectl get pods -n sentinel-apps -o wide

kubectl get services -n sentinel-apps

kubectl get deployments -n sentinel-monitoring

kubectl get pods -n sentinel-monitoring -o wide
```

Explain that Kubernetes runs multiple application replicas, monitors their health, and schedules workloads onto cluster nodes. Previously, your API gateway and frontend each had two available replicas, and Redis had one.


### Step 3 — Show the cloud API logs

```Shell
kubectl logs deployment/api-gateway -n sentinel-apps --tail=50
```



To follow logs live during the presentation:

```Shell
kubectl logs deployment/api-gateway -n sentinel-apps -f
```



Press `<span>Ctrl+C</span>` to stop following logs. This stops the log display, not the deployment.

### Step 4 — Open the AWS frontend through a temporary port-forward

First, verify the service:

```Shell
kubectl get service frontend-svc -n sentinel-apps
```

Then run this command in a dedicated PowerShell window:

```Shell
kubectl port-forward -n sentinel-apps service/frontend-svc 3001:80
```




While the command remains running, open:

[http://127.0.0.1:3001](http://127.0.0.1:3001?utm_source=chatgpt.com)

This forwards traffic from your laptop to the frontend service in AWS EKS. It does not create a public URL. If port `<span>3001</span>` is already occupied by your local frontend, use a different local port, for example:

```Shell
kubectl port-forward -n sentinel-apps service/frontend-svc 3101:80
```



Then open [http://127.0.0.1:3101](http://127.0.0.1:3101?utm_source=chatgpt.com).

Important: the frontend may be configured with a local or different API base URL. A loaded page alone does not prove that the AWS frontend is communicating with the AWS API. Verify its API calls in the browser's Developer Tools → Network before claiming a complete cloud end-to-end demo.



### Step 5 — Access the cloud API safely

In another PowerShell window:

```Shell
kubectl port-forward -n sentinel-apps service/api-gateway-svc 8001:8000
```



Keep it running, then test:

```Shell
Invoke-WebRequest http://127.0.0.1:8001/health -UseBasicParsing
```



Open the API docs at [http://127.0.0.1:8001/docs](http://127.0.0.1:8001/docs?utm_source=chatgpt.com) if the service exposes its OpenAPI documentation at that route.

### Step 6 — Access cloud Prometheus

Check its service first:

```Shell
kubectl get services -n sentinel-monitoring
```



If the `<span>prometheus</span>` service exposes port `<span>9090</span>`, use:

```Shell
kubectl port-forward -n sentinel-monitoring service/prometheus 9091:9090
```


Then open [http://127.0.0.1:9091](http://127.0.0.1:9091?utm_source=chatgpt.com) and execute the query:

```
up
```

If the service exposes a different port or the `<span>prometheus</span>` service name differs, use the values shown by `<span>kubectl </span><span>get </span><span>services</span>`. Stop each port-forward with `<span>Ctrl+C</span>` when you're finished.

To locate the actual implementation files, run:

```Shell
Get-ChildItem .\services\api-gateway -Recurse -File |
  Select-Object -ExpandProperty FullName

Get-ChildItem .\infrastructure\kubernetes -Recurse -File |
  Select-Object -ExpandProperty FullName

Get-ChildItem .\infrastructure\monitoring -Recurse -File |
  Select-Object -ExpandProperty FullName

Get-ChildItem .\.github\workflows -File -ErrorAction SilentlyContinue |
  Select-Object -ExpandProperty FullName
```

To locate health endpoints and API route definitions:

```Shell
Get-ChildItem .\services\api-gateway -Recurse -File |
  Select-String -Pattern '@router\.(get|post)|@app\.(get|post)|health' |
  Select-Object Path, LineNumber, Line
```



These searches help you identify the real code to open in VS Code. The table gives you the likely code areas; the commands establish the exact file paths in your current checkout.
